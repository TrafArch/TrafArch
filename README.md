# TrafArch

TrafArch 是一款 Android 交通卡读取工具。将卡片贴近手机，即可查看卡片信息、可读取的余额和最近行程；也可以保存卡片，之后随时查看已保存的记录。

[查看发布版本](https://github.com/TrafArch/TrafArch/releases) · [更新记录](CHANGELOG.md)

目前处于 Alpha 阶段，卡片兼容性和线路、站点识别仍在完善。不同城市、卡种与发行批次开放的信息可能不同，显示内容以实际读取结果为准。

## 可以做什么

- **查看卡片与余额**：读取支持的交通卡，显示卡片名称、可读取的余额及其他卡片信息。
- **查看最近行程**：展示卡内保留的交易和乘车记录，结合内置参考数据识别线路、站点，并按交通类型筛选。
- **管理已保存卡片**：保存读取结果、自定义卡片名称、查看历次保存的记录，以及删除或导出卡片记录。
- **解析乘车码**：通过相机扫描或从相册导入，查看符合 JT/T 1179 标准的交通一卡通乘车码信息。
- **查看详细信息**：“专家”页面提供更详细的卡片与读取结果，便于了解数据或协助排查问题。

应用提供信息读取与展示，不提供充值、支付或修改卡片功能。

## 安装与开始使用

### 使用要求

- Android 8.0 及以上。
- 读取实体卡需要手机支持 NFC，并在系统设置中开启 NFC。
- 相机扫码需要相机权限；也可选择“从相册导入”。没有 NFC 的设备仍可使用二维码图片导入功能。

可在本仓库的 [Releases 页面](https://github.com/TrafArch/TrafArch/releases)查看已发布版本及对应说明，安装适合手机的 APK。测试版本的兼容性可能随版本变化，更新前请阅读对应发布说明。

### 读取一张卡

1. 开启手机 NFC，打开 TrafArch，进入“首页”。
2. 在等待贴卡时，将卡片贴近手机背面的 NFC 感应区域，并保持不动，直到读取结束。
3. 在首页查看卡片信息与余额；进入“行程”查看本次读取到的记录。
4. 根据读卡后的提示选择是否保存。保存后可在“卡片”页面查看历史记录并修改名称。

如果希望每次读取后直接保存，可在“设置”中开启“读取后自动保存”。读卡结束后，使用首页的“再次读取”继续读取下一张卡。

上海交通卡的总余额默认扣除固定的 8 元可透支额度，相关读卡记录和已保存记录使用同一口径。“城市一卡通余额”本身不含这 8 元，始终保留读取值，不会重复扣除。例如总余额读到 89 元、城市一卡通余额读到 81 元，默认两项均显示 81 元。如需查看包含该额度的总余额，可在“设置 → 读卡与数据”中开启“上海交通卡可透支余额”。切换后立即生效；实际扣款、充值金额保持原值，扣除额度后的余额可显示为负数。

### 查看与导出记录

- **行程**：查看本次读取到的行程，可筛选轨道交通、公共汽电车等类型。完整行程以票据卡片展示进出线路、站点、时间、用时和扣款金额；点击卡片可分别查看进站、出站的原始记录与余额。
- **行程信息提示**：只有进站或上车记录时，只显示已知的信息。未读到出站或下车记录不一定代表仍在乘车，也可能是卡内记录被覆盖或本次读取不完整。
- **单次扣款公交**：没有上下车配对记录时，显示线路、日期和金额。
- **卡片**：列表与详情显示累计的“已保存记录”，包含历次保存及导入的记录；重复读取不会重复累加。只有旧版数字摘要而没有对应明细时，会注明“最近读取”，不会把它当作完整历史。
- **导出 JSON**：在“卡片”页面点击导出按钮，或在单张卡片的「⋯」菜单选择导出，再通过系统文件窗口选择保存位置。
- **完整备份**：保留卡片名称、历史读取批次和原始数据，适合换机、备份和恢复。
- **按字段导出**：勾选需要的时间、进出站点、进出线路、金额等内容，生成适合 workflow 处理的 JSON；未勾选的字段不会附带导出。不能确定进出方向时，可选择“站点／线路（未区分进出）”。
- **导入 JSON**：点击“卡片”页面的导入按钮，选择本应用导出的 JSON，检查预览后确认。完整备份会合并相同卡片的历史并保留本机自定义名称；按字段导出的文件作为单独的导入记录保存，缺失字段保持未知。

如需整理到飞书多维表格，可将 JSON 交给你使用的 workflow，读取文件中的 `records` 数组，将每条记录整理为一行。金额以十进制文本保存，卡号和站点编码保留前导零；未确认的数据为 `null`。应用不会自动上传文件或连接飞书。可查看[示例 JSON](docs/examples/trafarch-records.example.json)及[字段说明](docs/JSON_ARCHIVE_FORMAT.md)。

单个 JSON 文件上限为 32 MiB，超过时可按卡片分别导出。没有行程记录的卡片可选择“完整备份”。同一文件重复导入不会重复增加记录；如存在互相冲突的历史批次，应用会说明错误并保留原档案。旧版 TXT 文件仍可阅读，不作为恢复文件导入。

## 卡片与功能支持

| 类型 | 当前可用范围 |
| --- | --- |
| 交通联合卡 | 支持读取可公开访问的卡片信息、钱包余额、交易与乘车记录；线路和站点识别取决于卡内记录及参考数据。 |
| 城市一卡通 | 支持部分城市和卡种的信息、余额及记录读取，具体可读取内容因卡片而异。 |
| 地方交通卡 | 已有北京、上海、武汉通、羊城通、深圳通、苏州、天府通等读取路径；不保证上述城市的所有卡片版本均可读取。 |
| 部分 FeliCa 卡片 | 提供卡片识别及部分信息读取；Suica 可尝试读取开放服务中的余额与历史，取决于卡片和手机的 NFC 能力。 |
| 八达通相关产品 | 支持部分产品识别；目前尚未实现八达通港币钱包余额及交易记录读取。八达通全国通的交通联合侧金额不等于港币钱包余额。 |
| 交通一卡通乘车码 | 支持 JT/T 1179 标准的乘车码扫描与图片导入；不适用于所有支付码和城市自有格式的乘车码。 |

卡片通常只保留有限条最近记录。多次读取并保存可以留存应用已读到的信息，无法找回卡内已经被覆盖的旧记录。

交易明细与乘车过程记录的保存数量可能不同。例如，卡内可能有 10 笔交易明细和 30 条乘车过程记录；属于同一次操作的记录合并展示，其余过程记录仍保留。确定属于同一行程的进出记录会放在一张卡片中，因此行程卡片数可能少于原始记录数。可在“来源”筛选中选择“全部来源”，再点击卡片查看各侧记录。

部分交通联合卡每次只返回少量乘车过程记录，应用会继续读取后续记录。更新后重新贴卡并保持卡片不动，等待读取完成；补读到的进出记录可用于关联跨线路行程。同一终端的多次交易优先按各自时间对应。卡内已覆盖或未能读到的记录仍可能缺失，旧档案也无法凭空补回。

“已保存记录”与 JSON 导出的记录行采用相同统计口径。上海双应用卡的两侧原始记录分别计入，页面可以将相同记录折叠查看，因此这个数字可能大于行程卡片数。

轨道交通和分段计费公交支持将可靠对应的跨城进出记录放在同一张行程卡中。跨城行程的标题只显示“轨道交通”或“公共汽电车”，两端线路、站点和原始城市信息分别保留；异地卡在同一城市乘车时仍显示实际乘车城市。

没有读到进站记录，但有明确补票记录及可靠对应的后续出站时，也可以合并查看“补票 → 出站”。补票站名右上角以小字标注“补票”，下方显示补票时间，补票与出站金额分别显示；由于实际进站时间未知，这类行程不显示全程用时。存在多次补票、未闭合的进站或关联证据不足时，各条记录保留独立展示，单独的补票记录同样在站名右上角标注，点击仍可查看原始详情。

刷卡地区与发卡地区不同时，行程卡片右上角、更多菜单左侧显示“异地用卡”标识，轨道交通和公共汽电车均适用。跨城行程只要有一端在发卡地区之外使用，也会显示该标识。当前读取和已保存的历史行程均支持；发卡地区或刷卡地区未知时不显示。

进站记录早于交易明细的保留范围时，只要乘车过程记录仍有可靠的对应关系，也可以与出站记录一起显示。卡内不同来源记载的同一次上下车会合并在同一张行程卡中，点击后仍可查看各份原始详情；有冲突或无法确认的记录继续单独显示。

行程页顶部保留卡片名称、卡号和当前余额。已结束行程在扣款金额右侧显示行程后余额；无法可靠确定时显示“未知”，仅有进站记录时不显示扣款和行程后余额。大兴机场线扣款 50 元的记录标注“商务座”，深圳地铁 11 号线的席别暂不判断。

较早行程即使超出交易明细的保留范围，只要乘车过程记录中的扣款与余额能够互相核实，也可以显示行程后余额。已有档案保留了足够记录时，更新后重新打开即可显示，无需重新贴卡；原始记录余额仍可在详情中查看。过程记录之间若有充值，应用也会结合本次读取中已核实的充值和后续乘车余额交叉校验；例如扣款后 4.60 元，充值 10 元再乘公交扣 1.80 元，后续余额为 12.80 元时，可补齐这条行程的余额。记录不完整或余额存在冲突时，继续显示“未知”。

单次扣款公交也会结合相邻记录核实行程后余额。部分卡片在进站和出站记录中写入相同的扣款前余额，详情会同时保留“记录余额”并另列“出站后余额”；两者含义不同，应用不会改写卡片原始金额。旧档案缺少必要依据时，需要重新读取并保存后才能进一步确认。

已适配部分沈阳地铁乘车记录采用的特殊金额格式，修正这些记录出现巨额扣款和巨额记录余额的问题。更新后重新读取并保存，可得到正确金额；以前保存的批次继续保留当时的捕获结果，不会自动改写。“记录余额”可能是扣款前余额，只有依据充分时才另行显示行程后余额。

支持双应用读取的上海交通卡会分别保留交通联合与城市一卡通侧的数据，两侧余额独立显示。上海本地乘车记录可使用相应的本地终端资料识别线路和站点；进出站依赖账本推断时，详情会注明依据。两侧完全相同的记录收在可展开的“城市一卡通应用记录”中；独立的消费、充值和异地记录仍直接展示。能否读出取决于具体卡片及本次通信情况。

## 常见问题

### 手机没有反应，或提示读取失败

先确认手机支持 NFC 且已开启 NFC，再调整卡片与手机背面的位置。读卡时保持贴合，避免同时叠放多张卡；较厚的保护壳或金属配件也可能影响感应。

如果手机能够感应，但仍提示不支持或只有部分信息，可能是该卡种暂未适配、卡片没有开放相关数据，或本次通信未完成。可以重新读取，并按下方步骤提交日志。

### 为什么没有站名，或只显示线路、站点编码？

站名识别需要卡片实际记录与内置参考数据相匹配。未收录、编码含义不明或存在多种可能时，应用可能保留原始编码或显示“未匹配”。这不一定代表没有读到记录。

内置资料采用开发者按城市整理的线路、站点数据，包括天津地铁 7 号线。更新后重新读取卡片，新读取的记录会使用更新后的资料识别；已经保存的历史记录保留保存时的解析结果。更新站点资料无法找回卡内已被覆盖的旧记录。

已识别线路但站名为空时，应用会在该线路的已有数据中继续核对站点编码；仍无法确认时保留线路名和原始站点信息，不猜测站名。

部分北京记录虽然没有标明交通方式，仍可根据已有终端和地点资料显示线路、站名。地点匹配不会改变原交易类型；显示在地铁站点的单次消费，也不直接视为进出站或退资。重新读取并保存后，新识别的地点会随档案保留。

发卡城市与实际乘车城市可以不同；异地乘车记录应按该笔行程的信息理解。

### 扫码或相册导入无法识别

请先确认二维码属于支持的交通一卡通乘车码，并尽量使用清晰、完整、未遮挡的图片。

点击设置按钮旁的“扫码”进入独立页面，可使用应用内相机扫描或从相册导入，读取后在同页查看字段、发卡机构公钥证书和原始数据。相机扫码需要相机权限，识别模型随应用捆绑，不需要 Google Play 服务下载；相册导入另有内置解码方式，但仍受图片质量与二维码格式限制。

### 八达通全国通显示的金额和港币余额不同

交通联合侧金额与港币钱包余额的含义不同，不能直接互相替代。显示“港币余额未读取”时，表示本次没有读出实际港币钱包余额；请通过八达通官方渠道核对港币余额。

### 更新时提示与已安装应用不兼容

不同来源或签名的安装包可能无法直接覆盖安装，请核对对应版本的发布说明。卸载应用可能删除本地卡片档案，遇到更新错误时不要直接通过卸载解决。

## 数据与权限

- 已保存的卡片、读取快照和设置保存在本机；线路、站点识别使用随应用提供的本地参考数据。
- NFC 用于读取实体卡，相机权限用于应用内扫码。二维码识别在本地完成；在线反馈等功能需要网络。
- 卡片导出文件与运行日志可能包含卡片标识、交易时间、行程和终端信息。公开分享前，请先检查并遮盖不希望公开的内容。

## 反馈问题

可通过应用内“设置 → 反馈”中的 QQ 群或问卷提交问题。反馈时建议提供手机型号、Android 版本、应用版本、卡片种类，以及出现问题的操作步骤。

反馈问卷优先使用 Edge 的应用内浏览器打开，Edge 不可用时尝试 Chrome，网页选图由浏览器处理。请安装或启用其中一个浏览器；两者均不可用时，页面会提示并提供“复制问卷链接”。关闭问卷即可返回反馈页。

需要附上读卡日志时：

1. 在“设置”中开启“启用运行日志”（默认关闭）。
2. 返回首页重新读卡，复现问题。
3. 回到“设置”，点击“导出日志”。
4. 到手机的“下载”目录查找 `transit_card_log_*.txt`，检查其中的个人信息后再提交。
