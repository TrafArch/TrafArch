# CU 读取与显示边界

本文件记录当前 CU 读取实现与 Trip Reader 1.7.17 本地源码对照所得的结论。它不是实卡兼容性认证，也不表示两个应用的所有算法已经等价。

## 应用和文件

CU 使用 `A00000000386980701`。当前选择流程兼容带 Le 和不带 Le 的选择命令；未发现需要为上海另造 CU AID 或特殊 DF 的源码证据。原版常规路径先 CU 后 TU，当前上海组合路径先 TU 后 CU；本次保留既有顺序及各应用独立读取，未仅凭双应用类比删除 MF 选择或复用钱包结果。

记录角色由已解析的 CU 配置决定，不能仅用旧的标准 SFI 常量判断业务类型：

| 读取文件 | 角色 | 条件 |
| --- | --- | --- |
| `18` | 本地消费记录 | 通用 CU 读取 |
| `10` | 充值记录 | 通用 CU 读取 |
| `06` | 异地消费记录 | 派生城市代码为 `2000` 或 `2153` |
| `1A` | 异地消费记录 | 其他 CU 配置 |

每个循环文件逐槽读取，保留实际 SFI、槽位、卡内交易序号及完整响应数据体。槽位和交易序号不是同一个字段。标准文件解析 API 的原有默认 SFI 继续用于独立解析；运行时明确传入实际文件及角色。

依据为原版 `C0304d.m793j` 及 `apktool/smali/L0/d.1.smali` 约 28161、28203、28211、28228、28257 行。反编译 Java 的分支可能失真，条件以 Smali 和 case-safe 反编译结果交叉核对。

## 匹配与展示

- 使用记录原始第 10～15 字节的 HEX 终端编码查询。标准 BCD 视图非法时仍保留原始编码，不把 A–F 丢弃。
- CU 有独立显示投影，不把记录转换为 TU 交易后套用 TU 城市或行程算法。消费、充值、异地记录分别保留。
- 受理地区只由已核实的终端分类提供；发卡城市不能替代实际交易地区。缺少核心分类的终端保持未知。
- 保留原始交易日期和秒。涉及历史名称或深圳历史公交的查询使用 UTC+08 交易时间及完整规则条件；没有时间不猜测。
- 原始金额继续保留标准四字节字段及未确认单位，不根据文件名把未知金额当成人民币分。
- 上海 TU 与 CU 余额分别保存；TU 部分读取不导致主身份切换为 CU。终止性传输错误停止后续应用探测，卡片返回有效错误状态字则允许保留其他可用数据。
- CU 记录和匹配结果随读取快照保存，历史详情及文本导出使用捕获时结果。不同来源文件不相互合并；跨批次相同记录保留全部来源。旧版未保存该投影的档案保留已有原始证据，不自动补造当时的显示结果。

## 与原版仍有差异的范围

原版 `AbstractC0299a0.m757k` 先精确查询 `M0.o.a / M0.p.a / M0.q.a / M0.r.a / M0.C.c`，之后才在特定条件下使用 `L0.n.a` 前缀等回退。当前发布包未接入这组完整分类；已有前缀不能替代全部分类。尤其 `3100…` 终端可能涉及不同地区，不按前四位强行选城市。补充这些数据应走参考数据 CLI 和来源校验流程。

上海 CU 原版还使用 `07` 辅助记录：命令为 `00 B2 record 3C 10`，将打包时间与 `18` 记录配对，细分交通工具，并在严格条件下补充负余额。打包时间不是直接 BCD；证据在 `L0/d.1.smali` 约 9910～10174 行及 `B0/a.smali` 的 `s0 / t0`。本次尚未移植该层，不能据当前改动宣称全部上海车型、负余额解析已覆盖。

原版基础交易金额有三字节及类型定向的经验处理，当前标准视图保留四字节原文；两者不能在没有卡种证据时静默替换。

## 泉城通记录数量核对

2026-10-26 提供的日志中，`18` 成功读取 10 条；`1E` 成功读取 30 条，第 31 槽返回 `6A83`。完整 APDU 回放确认 30 条过程记录均可解析，其中 10 条与交易关联、20 条独立保留；另有一条无时间的 `1A` 公交记录，所以该样本的合并显示总数为 31。

当前源码未复现丢失 20 条记录。顶部原“交易 10 笔”只描述基础交易，本次改为显示合并后记录总数。来源筛选为 `18` 时仍只显示交易条目；“全部来源”显示全部。仓库回归使用合成卡号和行程复现 10/30 容量差异，验证完整读取、显示与归档；用户原始日志未加入仓库。

## 验证范围

自动化回归覆盖带/不带 Le 的应用选择、三类 CU 通道、原始 HEX、独立 CU 展示、上海组合结果、状态字拒绝与终止传输失败、普通 TU 不误走上海 CU 路径，以及 1E 优先关系。手机端仍需验收具体上海双标卡的选择响应、实际文件长度、记录内容和最终界面。
