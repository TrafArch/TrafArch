# Suica 行程解析接入

用户要求将所提供 SuicaReader APK 的 Suica 行程解析能力接入 TrafArch。
实现使用既有 Flutter / Dart NFC-F 读取架构，独立实现协议字段解释，不引入
APK 的 Android 应用代码、联网服务或写卡能力。

## 范围与决策

- 核对 090F 历史范围，包含块 0 最新记录，保留全部成功读取的数据与原始帧。
- 区分铁路、公交、购物、特殊及未知记录；解释日期、可用时刻、处理码、
  端末码、真实流水号、区域与进出站原码。未知字段不补猜。
- 交易后余额与相邻记录的余额差分别保留。断档、非法字段、最旧记录没有
  足够证据时不显示推算金额；余额差标明来源，不等同于保证准确的票价。
- 使用 APK 自带的 6435 条站点记录，原样保留 suica_stationcode.db，新增
  独立的离线提取/验证脚本及来源清单，不修改现有 TU/CU 包与清单，不重建
  当前缺失的旧参考数据工具。运行时验 SHA256，按区域/线路/站点精确查询。
- 接入现有读卡摘要和行程页，显示所有历史记录、站名/线路、原码及原文；
  将新增字段与当次展示结果冻结入恢复数据，并保留诊断证据。
- 档案当前要求逻辑卡号，Suica 当前只有 IDm。本次不改档案身份策略或表结构。
  Gallery 仍是独立模拟界面，不作为真实 NFC 功能入口。

## 固定约束

协议层不得依赖 Flutter、SQLite、app 或 feature；原生通道契约保持原样。
只读操作，不默认联网或上传。数据库原名/表名/记录/原码保留，交付报告前后
SHA256。保留工作区已有修改，AGENTS.md 不变。不编译 APK，不递增版本号。
日期使用 2026-11-16 对应 CHANGELOG 节。

## 验证

合成原始块测试须覆盖地区位、特殊/未知站点、日期精度、购物时刻、最新/最旧
记录、余额差和读卡中断；站库校验精确键、歧义和摘要；UI 验证完整列表与原码
回退；诊断及恢复保留新增信息。串行运行定向测试、全量 flutter test 与
flutter analyze。无实体卡数据时明确保留真机验收边界。
