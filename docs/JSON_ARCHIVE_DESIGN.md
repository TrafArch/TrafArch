# 卡片 JSON 存储与交换设计

## 用户需求与已明确边界

卡片数据使用版本化 JSON，支持导入、导出和旧档案兼容。导出可选择时间、进出站点、金额、进出线路等字段。目标是飞书多维表格；用户已明确客户的 workflow 负责处理文件，因此应用只需提供稳定、可遍历的 JSON，不需要登录或写入飞书。

## 实施选择

以下是本次实现的工程选择。SQLite 继续提供本机索引、事务及观察时间排序；增加按卡片保存的版本化 JSON 文档作为完整档案表示，旧摘要与历史批次无损迁入文档，现有读取快照 v1/v2/v3 保留原文。新文档与索引在同一事务内更新。保存、重命名、导入、删除均维护一致性。

完整备份使用 `format: trafarch.archive, version: 1, exportedAt, cards`，每张卡的文档为 `format: trafarch.card, version: 1, card, batches, fieldObservationTimes, importedRecords, retainedSummaries`。卡片摘要、用户名称、批次 ID、原始快照文本、CU 扩展和每字段观察时间均保留，未知快照内容不重解析。合并替换的摘要单独保留原始封套，有效行程仍可查看和导出，不伪造读取批次。卡面路径仅是已有元数据，不读取或复制任意外部文件。卡片和批次未知扩展保留；最外层备份封套的未知元数据无法无损分配到合并后的卡片，因此明确拒绝该类文件，防止静默丢弃。

按字段导出使用 `format: trafarch.records, version: 1, exportedAt, fields, records`。`records` 为平铺对象数组，UI 显示中文字段名，JSON 使用稳定英文键；只有选中的字段进入文件，原始快照不会附带进入裁剪文件。字段覆盖卡片名称/卡号、记录类型/来源、交易与进出时间、进出站名和编码、进出线路名称和编码、交易金额/币种/原始金额、余额、城市、终端。未知值用 null；标识符始终是字符串；未确认的时间和金额不推断。TU、CU 和未关联过程记录均覆盖。

两种文件都可导入。完整备份按卡指纹合并并保持已有自定义名称，重复批次不会重复添加；同批次 ID 的不同原文在预检中报告冲突，事务不写入。旧批次 ID 和余额来源引用保留。字段裁剪文件作为明确标记的导入记录保存，不能补造 NFC 原文或遗漏字段；无可靠卡片身份时形成独立导入档案，不能按相同显示名合并实体卡。重复文件/记录导入去重。文件格式或版本不支持、损坏、超限时明确报错；导入预览后由用户确认，一次事务完成。

## 界面与文件

卡片页提供导入和导出；支持全部卡片或单卡导出。导出对话框选择完整备份/指定字段，字段至少选择一个。所选卡片没有行程时提示改用完整备份。Android 使用系统文件选择器打开 JSON 和选择保存位置，取消操作不显示失败。空档案仍能导入。忙碌时禁用重复操作，数据库关闭等待导入完成。

## 验收

- 旧数据库迁移保留摘要、所有批次、观察时间、未知/损坏快照原文；迁移重复执行幂等。
- 全备份导出到空库再导出，业务数据一致；TU、CU、部分读取、旧快照、未知扩展均覆盖。
- 同文件重复导入、与本机既有卡片合并、批次冲突、失败回滚、名称/新鲜度保留。
- 字段裁剪不泄漏未选字段，不在隐藏原文中携带完整数据；保留前导零、未知金额单位和时间语义。
- 平铺字段文件导入可查看、重导出；文件损坏、未来版本、大小限制、取消和页面销毁测试。
- 系统文件通道测试、UI流程测试、完整 Flutter 测试、静态分析、Android 编译和原生测试。
- README 面向用户说明两种格式与 workflow 的 `records` 路径；提供不含真实用户信息的示例文件及字段说明。
